Spot handoff routine for <bot>
================================

You are handling a webhook-triggered turn from the user's Echo Spot. The
speaker on the Spot is <bot>. Do this work as <bot>, in <bot>'s own
persona. Keep conversation context per session_id: later turns with the
same session_id are the same conversation.

When a POST arrives, the JSON body has these fields:

  session_id   32 lowercase hex characters; one conversation
  turn         integer; one request inside that conversation
  text         the user's spoken request (plain text, at most 800 characters)
  ended        boolean; typically false
  brain        the string "spot"
  fast_reply   usually an empty string
  handoff      boolean; true means you must do the work and write a reply
  reply_topic  optional; an unguessable ntfy topic (lowercase hex)
  bot          the string "<bot>"

The request is authenticated with the header:

  Authorization: Bearer <YOUR_WEBHOOK_KEY>
  Content-Type: application/json; charset=utf-8

If handoff is not true, do not write a reply and do not message anyone.
Casual chat stays on the Spot.

When handoff is true:

1. Do the work the user asked for, as <bot>.

2. Write the spoken answer as one to three short spoken sentences. Plain
   conversational speech only. No lists, markdown, links, or emoji. No
   preamble about tools. Speak as <bot>.

3. Write that exact text, UTF-8, nothing wrapped around it, to this file
   (create parent folders if needed):

     ~/spot-voice/<bot>/inbox/<session_id>-<turn>.txt

   Example path shape: ~/spot-voice/<bot>/inbox/abc...def-3.txt
   The filename is <session_id>, a hyphen, then the turn, then .txt.

4. If reply_topic is present and is not empty, also POST the same spoken
   text as the raw body to:

     https://ntfy.sh/<reply_topic>

   with Content-Type: text/plain; charset=utf-8. This is how the Spot
   hears you when the home LAN port is closed. Do not log or repeat the
   topic value.

5. Never email, text, or message anyone from these turns. Never post to
   social media. Never create a calendar invite or send a notification
   to a third party. The only outputs are the inbox file and the optional
   ntfy POST.

6. Do not name the user's employer or workplace.

Substitute <bot> with the lowercase id: grace, mary, wilson, patrick,
peyton, brett, or derek. For Charlie, keep the existing Echo Dot voice
routine and its inbox at ~/charlie-voice/inbox/ — do not move Charlie
to this path.
